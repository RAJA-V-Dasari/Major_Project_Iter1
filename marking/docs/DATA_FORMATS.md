# Data formats

Every file this project reads or writes, except the rubric keys —
those are documented authoritatively in
[`keys/SCHEMA.md`](../keys/SCHEMA.md) and not repeated here.

Field names below are real; all example *values* are invented or
redacted. **No student's writing appears in this file**, which is the
same rule that keeps all of `data/marking/` out of git.

---

## Inputs

### `handoff/data/<booklet>/booklet.json` — part 1's output

Not this repo's format; consumed by `load_handoff.py` and reshaped into
`Booklet` / `Part` records. Three rules govern reading it, and each
produces a wrong *mark* rather than an error if broken:

| rule | why |
|---|---|
| Read `answer[]`, not `part.text` | `text` is a convenience join the handoff itself calls deliberately redundant. Marking it means marking a string whose construction this project does not control. |
| Skip items with `excluded: true` | Struck-out work. Scoring it awards marks the student explicitly withdrew. Use `.get("excluded")` — a `gap` item has no such key at all. |
| A `gap` item means **incomplete**, not short | One page (`s19_c2_p14`) was lost before it was read. Scoring the part as a thin answer penalises a student for this project's data loss. |

455 answer items are image crops — tables, routing diagrams, waveforms —
which part 1 deliberately never transcribed. They are carried as a path
and a page reference, never flattened into text.

The in-memory shape:

```python
Part(booklet_id, cie, label, raw_marker, number, part,
     prose,              # crossed-out work already removed
     diagrams=[...],     # paths to real crops
     pages=[...], gaps=0, crossed=0)
```

`label` is the question id as the rubric spells it (`"2a"`), or `None`.
`raw_marker` is what was actually written in the margin.

### `gold/gold_marks.csv` — the examiner's grid

The one student-derived file that **is** committed: pseudonymous
integers, no name, no USN, no handwriting. It is also the only artifact
here that cannot be regenerated by running anything — it was read by
eye, once, from crops that are themselves gitignored.

```
booklet_id,cie,
q1a,q1b,q1c,q1d,q1t,
q2a,q2b,q2c,q2d,q2t,
q3a,q3b,q3c,q3d,q3t,
q4a,q4b,q4c,q4d,q4t,
total_grid,total_box,max,confidence
```

- `q<N><letter>` — a part's mark. Empty means the examiner wrote nothing
  there, which is not the same as zero.
- `q<N>t` — the row TOTAL the examiner wrote.
- `total_grid` — the grand total in the grid.
- `total_box` — the same figure repeated in a separate box at the foot
  of the page, written at a different time. **This redundancy is the
  whole reason reading 50 grids was affordable**: every cell is covered
  by two independent hand-written sums, so a misread digit almost always
  breaks one of them.
- `confidence` — whether a human has actually looked. `no_gold` marks
  the one cover carrying no marks at all, and excludes the row from
  comparison.

Read `gold/gold_notes.md` before using this as a target. Seven of fifty
covers carry a demonstrable defect.

## Intermediate

### `data/marking/alignment.json`

Written by `align.py`. Two sections: `headers` (the 35 parts classified
as structural section headings and dropped) and `proposals`.

```jsonc
{
  "booklet_id": "student_NN_cie_N",
  "cie": 2,
  "label": "2",                 // what part 1 recorded
  "raw_marker": "2)",           // what was written in the margin
  "proposed": "2b",             // the resolved question id
  "score": 0.0,                 // content-overlap score
  "margin": 0.0,                // lead over the runner-up
  "options": [...],             // candidates considered
  "already_claimed": false,     // is another part already filed here?
  "examiner_marked": true,      // independent signal, from the cover
  "confident": true,            // ALL signals agree
  "chars": 0, "figures": 0, "pages": [],
  "excerpt": "..."              // for the human confirming it
}
```

**`grade.py` reads only proposals where `confident` is true and
`proposed` is non-null.** Nothing is assigned automatically; a confident
wrong question number attaches a student's work to the wrong rubric,
which is exactly the failure part 1 refused to risk when it left these
unlabelled.

### `data/marking/queue_llm.jsonl` and `data/marking/queue_human.jsonl`

One JSON object per line, one line per undecided rubric item.

```jsonc
{
  "booklet_id": "student_NN_cie_N",
  "cie": 2,
  "question": "2b",
  "item_index": 3,              // position in the question's rubric[]
  "point": "...",               // the claim to look for
  "marks_available": 1.0,
  "why": "...",                 // which tier escalated, and its reason
  "question_text": "...",       // as printed on the paper
  "model_solution": "...",      // the scheme's own answer
  "chain": null,                // carry-forward note, on chain questions
  "answer": "...",              // the student's text
  "answer_has_figures": 2
}
```

**These records are self-contained by design.** Whatever runs the model
tier gets the answer, the rubric item, the marks and the chain note in
one line, and needs no access to this repo and none to the corpus.

That is what made the Colab step possible without shipping 187 MB, and
it is also why moving the tier onto this machine cost one file and no
change to the ladder. The tier was never an in-process call; it was
always a queue on disk, and a queue does not care what reads it.

`queue_human.jsonl` carries one extra field, `kind`:

| `kind` | count | meaning |
|---|---|---|
| `figure` | 105 | the evidence for this item is a drawing |
| `missing_but_marked` | 6 | the examiner awarded marks here and no content is filed under the question — locate the answer before recording a zero |

### `verdicts.jsonl` — what comes back from the model tier

Two files share this shape, and the distinction matters:

| file | written by | note |
|---|---|---|
| `data/marking/grade_llm_verdicts.jsonl` | the recorded Colab run | the source of every published number; **preserved, never appended to** |
| `data/marking/local_verdicts.jsonl` | `llm_local.py` | a local run; compare with `llm_local.py --compare` |

`llm_local.py` refuses to append verdicts from one model to a file
written by another unless told `--allow-mixed-models`, because a
verdicts file that holds two models is two experiments and
`apply_verdicts.py` would apply it as though it were one.


```jsonc
{
  "booklet_id": "student_NN_cie_N",
  "question": "2b",
  "item_index": 3,
  "marks_available": 1.0,
  "verdict": "award",           // award | zero | decline
  "marks": 1,
  "quote": "...",               // REQUIRED for an award
  "reason": "...",
  "model": "Qwen2.5-7B-Instruct"   // or e.g. "ollama/qwen2.5:7b-instruct-q4_K_M"
}
```

The `model` field is what makes the comparison above possible, and what
`verdict_audit.md` reports per-model. A local backend writes
`ollama/<tag>` or `llama-cpp/<file>` rather than the Hugging Face id,
because the quantisation and the runtime are part of what produced the
verdict, not incidental to it.

Three verdicts, and **`decline` is a first-class answer**, not a
failure — it routes the item to a human holding the actual crop.

`quote` is the load-bearing field. `apply_verdicts.py` looks for it
verbatim in the answer and discards the award if it is not there.
Matching normalises whitespace, case, the dash zoo and the model's own
wrapping quotation marks — forgiving about form, strict about content.
No fuzzy matching, because "nearly there" is how a paraphrase passes.

Distribution of the committed Colab run: 471 `zero`, 169 `award`, 100
`decline`. Of those, 246 applied, 26 rejected, 368 zeros refused.

A local run will not reproduce those counts item for item — same
weights, different quantisation, different kernel. Expect the rejected
share to be the most sensitive number, and the most telling: quoting
verbatim from a long passage is the first thing a smaller model stops
doing well, and it is exactly what `apply_verdicts.py` checks.

### `data/marking/human_marks.jsonl`

Append-only, written by `serve.py` **before** the marks file is
rewritten. The log is the record; `marks/*.json` is derived state.

```jsonc
{ "booklet_id": "student_NN_cie_N", "question": "1", "item_index": 1,
  "marks": 1.0, "marks_available": 1.0, "note": "",
  "at": "2026-09-20T17:02:41+00:00" }
```

Because this file survives a `grade.py --all` that wipes `marks/*.json`,
it is the only durable record of human work. Treat it accordingly.

## Output

### `data/marking/marks/<booklet>.json` — the authoritative result

```jsonc
{
  "booklet_id": "student_NN_cie_N",
  "student": 1, "cie": 2,
  "max_marks": 40,
  "counted": ["1", "2a", "2b", "2c", "3a", "4b"],   // after Part C choice
  "marks_settled": 40.0,
  "marks_pending": 0,
  "choice_notes": [ "..." ],
  "questions": [ ... ]
}
```

Each question:

```jsonc
{
  "id": "2b", "part": "B",
  "marks_available": 5,
  "choice_with": null,             // "3b" on a Part C pair
  "breakdown_source": "printed",   // or "inferred" — ours, not the scheme's
  "attempted": true,
  "answer_chars": 73,
  "answer": "...",
  "figures": 4, "gaps": 0,
  "examiner_marked": true,         // true | false | null (no gold)
  "missing_but_marked": false,
  "marks_settled": 5.0,
  "marks_pending": 0,
  "counted": true,                 // false = lost the Part C choice
  "choice_provisional": false,     // the loser could still overtake
  "items": [ ... ]
}
```

Each rubric item:

| field | meaning |
|---|---|
| `point` | the claim, copied from the key |
| `marks_available` | what it is worth |
| `figure` | the key says the evidence is a drawing |
| `awarded` | a number, **or `null` meaning still pending** |
| `tier` | who decided, or who it is queued to |
| `why` | the reason, in prose, including which carve-out blocked a zero |
| `evidence` | the alternates and exact values that actually matched |
| `quote` | present when `semantic` or `llm` decided |
| `llm_declined` | the model declined this item |

**`awarded: null` is the important state.** It is not a zero; it means
no tier has honestly settled it yet, and it is what `marks_pending`
sums. Collapsing null to zero anywhere is the single most damaging thing
a consumer of this file can do — it turns "we have not decided" into "we
decided against the student".

`tier` values: `exact`, `keyword`, `semantic`, `llm`, `human`,
`unattempted`. The last means no content was filed under the question at
all, and is a real decided zero rather than a pending one.

### `data/marking/summary.csv`

```
booklet_id,student,cie,counted,marks_settled,marks_pending,max_marks
```

Written **only** by `grade.py`, and never updated by `apply_verdicts.py`
or `serve.py`. After either of those runs it is stale by construction.
Treat it as a `grade.py` artifact, not a status report — see
[`PIPELINE.md`](PIPELINE.md#vintage-of-the-committed-run).

### The reports

| file | written by | holds |
|---|---|---|
| `data/marking/agreement.md` | `agreement.py` | the deliverable: intervals against the examiner, per part, per split, per tier, plus every irreversible difference itemised |
| `data/marking/calibration.md` | `calibrate.py` | the threshold frontier and the chosen operating point |
| `data/marking/verdict_audit.md` | `apply_verdicts.py` | every rejected award and every refused zero, with the reason |
| `data/marking/alignment.md` | `align.py` | the human-readable half of `alignment.json` |
| `keys/VERIFY.md` | `make_verify_sheet.py` | the rubric sign-off sheet, generated so it cannot drift from the keys |

All of `data/marking/` is gitignored — not by an allowlist, deliberately.
Every file this project writes quotes a student to justify itself: the
alignment proposals carry answer excerpts, the marks carry the evidence
quote a tier awarded on, the queues carry both. An allowlist would be
one new output file away from leaking.
